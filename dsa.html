Data Structures Behind SmartRoute

📊 Graph

Stations = Vertices
Routes = Weighted Edges
Each edge carries mode, distance, time, fare and optional route number. Directed to model one-way constraints if needed.

📋 Adjacency List

Map<stationId, List<{to, edge}>>
Efficient storage of sparse transport networks. Neighbors of a station are retrieved in O(degree) time.

⚡ Priority Queue (Min-Heap)

Used inside Dijkstra to always expand the node with currently smallest cost (distance / time / fare / transfer-cost).

🔍 Dijkstra’s Algorithm

Four variants by changing the weight function:
• Distance
• Travel time
• Fare
• Transfer penalty + time

🗃️ Hash Table

Station name → id lookup and id → station object. Enables fast exact and partial search (autocomplete).

↩️ Path Reconstruction

Predecessor map stores previous node and the edge used. Walking backwards from destination rebuilds the full multimodal path.

When you search Pune Railway Station → VIT Pune, Dijkstra explores these and many other edges according to the chosen weight.

Key Functions

  • findShortestDistance() — weight = distance
  • findFastestRoute() — weight = time
  • findCheapestRoute() — weight = fare
  • findMinimumTransferRoute() — weight = transfer penalty + time
  • findAllRoutes() — runs multiple Dijkstra variants + mode restrictions
  • searchStation() — hash-backed partial match
  • reconstructPath() — predecessor walk
