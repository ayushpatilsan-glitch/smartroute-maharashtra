Problem

Finding a suitable public transportation route in a city like Pune requires comparing multiple factors at once: distance, travel time, fare, number of transfers and available modes (bus, metro, auto, train, etc.). Manual comparison is slow and incomplete.

Solution

A graph-based multimodal route planning system that:

  • Models stations as vertices and transport links as weighted edges
  • Runs Dijkstra’s algorithm with different weight functions (distance, time, fare, transfers)
  • Returns all meaningful routes, not only a single “best” path
  • Lets the user compare options side-by-side and inspect step-by-step details

Data Structures Used

  • Graph — overall network
  • Adjacency List — efficient neighbor storage
  • Hash Table (Map) — station name ↔ id lookup and autocomplete
  • Priority Queue (Min-Heap) — Dijkstra expansion order
  • Arrays / Lists — path storage, route lists, steps

Algorithms

  • Dijkstra’s Algorithm — shortest path for non-negative weights
  • Path Reconstruction — via predecessor map
  • Route Comparison — multi-metric ranking and filtering
  • Station Search — exact + partial, case-insensitive

Project Flow

USER ↓ Enter Source & Destination ↓ Station Search (Hash Table) ↓ Access Graph (Adjacency List) ↓ Dijkstra + Priority Queue · Shortest Distance · Fastest Time · Cheapest Fare · Minimum Transfers ↓ Path Reconstruction ↓ Generate Multiple Routes ↓ Compare & Filter ↓ Display All Routes + Details

Geographical Focus

Primary demonstration: Pune and Pimpri-Chinchwad (PCMC) metropolitan region. Sample stations include Pune Railway Station, Swargate, Shivajinagar, Civil Court, Katraj, Hinjawadi, VIT Pune, Airport, and many more.

The data model is designed so additional Maharashtra cities (Mumbai, Nagpur, Nashik, Kolhapur, etc.) can be added later as separate subgraphs or layers.

Important Notes

  • All distances, times and fares are sample / estimated demo values.
  • This is not live traffic, live bus tracking or official fare data.
  • Architecture separates static data from potential future live services.

Technology

  • Frontend: HTML5, CSS3, Vanilla JavaScript
  • No framework required — pure static site, ideal for GitHub Pages
  • Core algorithms cleanly separated in graph.js
